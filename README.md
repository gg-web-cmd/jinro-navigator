# 진로 잠재력 내비게이터

**초·중·고 학교급을 학생이 직접 고르면, 그 수준에 맞는 문항 세트로 DISC·MBTI·다중지능·RIASEC 네 가지 검사를 풀고 곧바로 채점 결과를 봅니다.**
**네 검사를 모두 마치면 학교급에 맞춰 조언 수준이 달라지는 AI 종합 진로보고서를 만들어 인쇄·워드 저장·텍스트 복사로 내보낼 수 있습니다.**
**Node.js와 Express로 만든 작은 웹앱이라 `npm start` 한 줄로 돌아가고, 학생 답변은 서버가 아니라 학생 브라우저에만 저장됩니다.**

> 배포(인터넷 주소 만들기)는 [DEPLOY.md](DEPLOY.md)에 따로 정리해 두었습니다.
>
> **바로 써 보기:** https://gg-web-cmd.github.io/jinro-navigator/ — 깃허브 페이지스에는 서버가 없어 AI 대신 기본 분석 엔진으로 보고서가 만들어집니다.

## 1. 학교급별 문항 구성

고른 급에 따라 **척도(유형) 하나당 문항 수**가 달라지고(초 3 · 중 5 · 고 7), 그래서 총 문항 수도 달라집니다.
아래 숫자는 `node scripts/check-questions.mjs` 를 실제로 돌려 나온 값입니다.

여기에 종합 보고서 생성 시간 **1~2분**이 더 붙습니다(앱 안내 문구 기준).
초등급은 문항뿐 아니라 **척도 라벨과 유형 설명도 쉬운 말 버전**으로 바뀝니다. (예: "매우 그렇다" → "완전 나야")

### 문항 내용은 2026년 기준으로 새로 썼습니다

- 생성형 AI(챗봇으로 찾은 답을 다시 확인하기), 숏폼 영상 만들기, 기후·환경 같은 지금 아이들의 생활 소재가 문항에 들어 있습니다.
- 유형 설명과 직업 예시도 2026년 시점에 맞춰 갱신했습니다.
- 프롬프트에도 2026년 공통 지침이 들어 있어, AI 보고서가 **"이 직업은 사라진다" 같은 겁주는 표현을 쓰지 않고**, AI를 함께 쓰는 도구로 삼아 일하는 모습을 그려 주도록 되어 있습니다. (`lib/prompt.js` 의 `ERA_2026`)

### 보고서 조언이 급마다 다릅니다

| 학교급 | 보고서에서 달라지는 부분 |
|---|---|
| 초등 | 학과·전공·대학·입시 이야기를 **한 글자도 쓰지 않습니다.** "관심 가져볼 만한 학과 5가지"는 **"더 알고 싶은 직업 세계 5가지"** 로, SWOT은 **"나의 보물지도"**(잘하는 것 / 더 크는 중인 것 / 나를 도와줄 기회 / 조심할 점)로 바뀝니다. |
| 중학 | 자유학기(자유학년) 주제선택·진로탐색, 동아리 선택, 3학년 2학기 진로연계학기와 연결합니다. 고교 유형(일반고·특성화고·특목고·마이스터고) 힌트를 한 단락 넣되 단정하지 않습니다. 학과는 **계열 수준**으로만 넓게 제시합니다. |
| 고교 | 고교학점제 선택과목을 **일반선택 / 진로선택 / 융합선택**으로 나눠 추천하고, 학생부 관점(탐구활동·독서·동아리)을 제시하며, 학과는 **실제 존재하는 구체적 학과명**으로 씁니다. 입시 제도·합격 가능성은 단정하지 않습니다. |

이 차이는 AI 보고서뿐 아니라 **키 없이 도는 폴백 보고서에도 똑같이 적용**됩니다. 다만 위 괄호 안의 네 칸 이름은 AI에게 주는 지시문(`lib/prompt.js`) 기준이고, 폴백 보고서(`lib/fallback.js`)는 같은 네 칸을 "내가 이미 가진 보물 / 더 키우면 좋을 보물 / 나를 도와줄 사람과 기회 / 조심하면 좋은 것"이라는 조금 다른 말로 씁니다.

## 2. 빠른 시작

### 1) Node.js가 깔려 있는지 확인

```
node -v
```

`v18.0.0` 이상이면 됩니다(`package.json` 의 `engines` 가 `>=18`). 숫자가 안 나오고 오류가 뜨면 [nodejs.org](https://nodejs.org)에서 LTS 버전을 설치한 뒤 터미널을 새로 열어 다시 확인하세요.

### 2) 프로젝트 폴더로 이동

```
cd C:\vibe\진로
```

### 3) 필요한 패키지 설치 (처음 한 번만)

```
npm install
```

설치되는 것은 `express` 와 `dotenv` 두 개뿐입니다.

### 4) 설정 파일(.env) 만들기

```
copy .env.example .env
```

macOS·Linux라면 이렇게 합니다.

```
cp .env.example .env
```

API 키가 없어도 앱은 동작합니다. 아래 3번 항목을 보고 키를 넣으면 AI 보고서가, 비워 두면 기본 분석 엔진 보고서가 나옵니다.

### 5) 문항 데이터가 정상인지 확인 (선택)

```
npm run check
```

"모든 검사를 통과했습니다"가 나오면 문항 수·유형 분포·중복 여부가 모두 정상입니다.

### 6) 서버 실행

```
npm start
```

터미널에 아래처럼 뜨면 성공입니다.

```
  진로 잠재력 내비게이터 서버가 시작되었습니다.
  접속 주소  : http://localhost:3000
  AI 연결    : 설정됨 (모델 solar-pro4)
  종료하려면 Ctrl + C 를 누르세요.
```

### 7) 브라우저로 접속

```
http://localhost:3000
```

서버를 끄려면 터미널에서 `Ctrl + C` 를 누릅니다.
파일을 고치면서 작업할 때는 `npm start` 대신 아래를 쓰면 서버 파일이 바뀔 때 자동으로 재시작됩니다.

```
npm run dev
```

## 3. Upstage API 키 발급과 .env 작성

이 앱의 AI 보고서는 Upstage의 Solar 모델(`https://api.upstage.ai/v1/chat/completions`)을 호출합니다.

### 키 발급

1. [https://console.upstage.ai](https://console.upstage.ai) 에 접속해 로그인(또는 회원가입)합니다.
2. 콘솔에서 **API Keys**(API 키) 메뉴로 들어갑니다.
3. 새 키를 발급하고, 화면에 표시된 키 문자열을 복사합니다. 키는 발급 직후에만 전체가 보이는 경우가 많으니 그 자리에서 복사해 두세요.
4. 사용량과 잔여 크레딧도 같은 콘솔에서 확인할 수 있습니다. (콘솔 화면 구성은 서비스 쪽 사정으로 바뀔 수 있습니다.)

### .env 작성

프로젝트 폴더(= `server.js` 가 있는 폴더)의 `.env` 파일을 메모장으로 열고 아래처럼 채웁니다.

```
UPSTAGE_API_KEY=up_여기에_발급받은_키를_붙여넣기
UPSTAGE_MODEL=solar-pro4
PORT=3000
```

- 따옴표 없이, `=` 앞뒤에 빈칸 없이 붙여 씁니다.
- `.env` 를 고친 뒤에는 **서버를 껐다 다시 켜야** 반영됩니다.
- `UPSTAGE_MODEL` 은 특별한 이유가 없으면 그대로 두세요. 비워 두면 `solar-pro4` 가 쓰입니다.
- `PORT` 는 3000번이 이미 쓰이고 있을 때만 바꾸면 됩니다.

이 세 개가 이 앱이 읽는 환경변수의 전부입니다.

### ⚠️ 키는 절대 깃허브에 올리지 마세요

- API 키는 **비밀번호와 같습니다.** 공개 저장소에 올라간 키는 자동 수집 봇이 몇 분 만에 찾아내 남의 결제로 쓰입니다.
- 이 프로젝트의 `.gitignore` 에는 이미 `.env` 와 `.env.*` 가 들어 있고 `.env.example` 만 예외로 두었습니다. **`.env.example` 만 커밋하고 `.env` 는 절대 커밋하지 마세요.**
- 키를 코드 안(`server.js` 등)에 직접 적어 넣지 마세요.
- 실수로 올렸다면 커밋을 지우는 것만으로는 부족합니다. **Upstage 콘솔에서 해당 키를 즉시 폐기(revoke)하고 새 키를 발급**하세요. 자세한 사고 대처 순서는 [DEPLOY.md](DEPLOY.md) 2번에 있습니다.
- 학생 PC에 프로젝트 폴더를 통째로 복사해 나눠 줄 때도 `.env` 는 빼고 주세요.

## 4. 키가 없어도 완전히 동작합니다 (폴백 보고서)

키를 넣지 않았거나, 넣었는데 호출이 실패해도 앱은 **오류 화면 대신 보고서를 반드시 돌려줍니다.** `lib/fallback.js` 의 규칙 기반 엔진이 검사 결과를 그대로 읽어 **학교급에 맞는** 보고서를 만들어 줍니다.

폴백으로 넘어가는 경우는 세 가지이고, 각각 화면에 다른 안내 문구가 뜹니다.

| 상황 | 화면 안내 |
|---|---|
| `.env` 에 키가 없음 | "AI 연결 설정이 아직 되어 있지 않아, 기본 분석 엔진으로 보고서를 만들었어요." |
| 키 오류·네트워크 오류·120초 시간 초과 | "AI 서버와 연결이 원활하지 않아, 기본 분석 엔진으로 보고서를 만들었어요." |
| 같은 IP에서 1시간에 30회 초과 | "지금 보고서 요청이 많아 기본 분석 엔진으로 보고서를 만들었어요." |

폴백 보고서도 학생의 실제 점수·유형·순위를 정확히 반영하고, 초등이면 "나의 보물지도", 중학이면 자유학기·고교 유형, 고교면 고교학점제 선택과목까지 급별로 다르게 나옵니다. 다만 AI 보고서처럼 네 검사를 자유롭게 엮어 새 문장을 쓰지는 못하고 미리 준비된 설명을 조합하므로, 학생마다 겹치는 문장이 생깁니다.

보고서 화면 위쪽에 어떤 엔진으로 만들었는지 표시되고(`solar-pro4` 또는 `rule-based`), 폴백일 때는 안내 상자와 함께 **"🔄 다시 생성"** 버튼으로 재시도할 수 있습니다.

> **참고:** 키를 넣지 않으면 서버가 Upstage를 아예 호출하지 않습니다. 즉 **검사 결과가 외부로 나가지 않습니다.** 개인정보가 특히 조심스러운 상황이라면 키 없이 운영하는 것도 정당한 선택지입니다.

## 5. 폴더 구조

```
진로/
├─ package.json               앱 이름·실행 명령(start / dev / check)·의존성 정의
├─ package-lock.json          설치된 패키지 버전 고정 파일 (건드리지 않음)
├─ server.js                  Express 서버. 정적 파일 서빙 + 보고서 API + 급별 폴백 처리
├─ render.yaml                Render 배포 설계도(빌드·시작 명령, 환경변수 목록)
├─ DEPLOY.md                  깃허브 + Render 배포 안내서
├─ README.md                  이 문서
├─ .env.example               설정 파일 견본. 복사해서 .env 로 쓰는 원본
├─ .env                       실제 설정 파일(직접 만듦). API 키가 들어 있어 깃 제외 대상
├─ .gitignore                 node_modules · .env 등을 깃에서 제외하는 목록
├─ node_modules/              npm install 이 만든 패키지 폴더 (건드리지 않음)
│
├─ .github/
│  └─ workflows/ci.yml        깃허브에 push 할 때마다 문법 검사 + npm run check 자동 실행
│
├─ scripts/
│  └─ check-questions.mjs     문항 검증기. 급별 문항 수·유형 분포·중복을 세어 확인 (npm run check)
│
├─ lib/                       서버에서만 쓰는 코드
│  ├─ prompt.js               AI 지시문. PERSONA + 출력 규칙 + 급별 LEVEL_RULES + 2026 공통 지침
│  └─ fallback.js             AI 없이 검사 결과만으로 급별 보고서를 만드는 규칙 기반 엔진
│
└─ public/                    브라우저로 그대로 내려가는 파일들
   ├─ index.html              화면 껍데기. 실제 화면은 전부 js/app.js 가 그림
   ├─ css/
   │  └─ style.css            전체 디자인·다크모드·인쇄용 스타일
   └─ js/
      ├─ app.js               앱 컨트롤러. 학교급 선택, 화면 이동, 답 저장, 키보드 조작, 보고서 생성 총괄
      ├─ ui.js                모든 화면(홈·학교급·학생정보·문항·결과·요약·보고서) 그리기와 급별 문구 사전
      ├─ report.js            보고서 마크다운 렌더링, 인쇄·워드·마크다운·복사, 서버에 보고서 요청(SSE)
      ├─ scoring.js           네 검사 채점 로직. 만점은 문항 데이터에서 자동으로 계산됨
      ├─ storage.js           localStorage 저장·불러오기, 보관함, JSON 내보내기/가져오기
      ├─ tests.js             급별 검사 레지스트리. getTests(급) 하나로 문항·척도·예상시간을 묶어 돌려줌
      └─ data/
         ├─ levels.js         ★ 학교급 정의. perScale·counts·total·estMinutes·급별 정책 문구
         ├─ disc.js           DISC 급별 문항(12/20/28) + 4개 유형 설명(기본·쉬운 말)
         ├─ mbti.js           MBTI 급별 문항(12/20/28) + 4축(EI·SN·TF·JP) 정의
         ├─ mbti-results.js   MBTI 16유형 결과 문구(기본·쉬운 말)
         ├─ mi.js             다중지능 급별 문항(24/40/56) + 4점 척도
         ├─ mi-types.js       8개 지능 설명과 상위 2개 조합 해설(기본·쉬운 말)
         └─ riasec.js         RIASEC 급별 문항(18/30/42) + 6개 유형 설명
```

★ `levels.js` 는 **이 앱의 중심 파일**입니다. 서버(`server.js`, `lib/prompt.js`, `lib/fallback.js`)와 브라우저(`tests.js`, `app.js`, `ui.js`), 그리고 검증 스크립트(`scripts/check-questions.mjs`)가 모두 이 파일을 직접 불러 씁니다. (`storage.js` 와 `scoring.js` 는 `tests.js` 를 거쳐 간접적으로 씁니다.) 여기 값을 고치면 문항 수·보고서 분량·화면 문구가 한꺼번에 따라 바뀝니다.

서버가 제공하는 주소는 세 개뿐입니다.

| 주소 | 하는 일 |
|---|---|
| `GET /api/health` | 서버 상태·키 설정 여부·모델 이름을 JSON으로 알려 줌 |
| `POST /api/report` | 보고서를 한 번에 받아옴 |
| `POST /api/report/stream` | 보고서를 글자가 흘러나오듯 실시간으로 받아옴(SSE) |

앱은 항상 스트리밍을 먼저 시도하고, 실패하면 자동으로 일반 방식으로 한 번 더 요청합니다.

## 7. 개인정보 안내

### 서버에 남지 않습니다

- 학생이 입력한 **이름·학교·학년**과 **모든 문항 응답**은 그 학생 브라우저의 localStorage에만 저장됩니다. 저장 키는 아래 두 개입니다.
  - `jinro_session_v2` — 진행 중인 검사 한 건
  - `jinro_archive_v2` — 보관함, 최대 20건
- 서버(`server.js`)에는 데이터베이스도, 파일에 기록하는 코드도 없습니다. 보고서 요청을 처리하는 동안 메모리에만 잠깐 머물렀다 사라집니다. 서버 콘솔에는 오류가 났을 때 오류 메시지와 학교급 이름만 찍히고, 학생 이름이나 답변은 찍히지 않습니다.
- 서버가 기억하는 유일한 것은 남용을 막기 위한 **접속 IP와 요청 시각**뿐이며, 1시간이 지나면 자동으로 지워집니다.
- 참고로 화면 글꼴을 위해 `index.html` 이 **Google Fonts** 를 한 번 불러옵니다. 검사 내용과는 무관하지만, 외부 요청이 아예 없어야 하는 환경이라면 이 줄을 지우고 시스템 글꼴을 쓰면 됩니다.

### "보고서에 내 이름을 넣어 주세요" 스위치

학생 정보 입력 화면에는 체크박스가 하나 있습니다. **기본값은 꺼짐(체크 안 됨)** 이고, 이 값은 세션의 `sendName` 필드에 저장됩니다.
보고서를 만들 때 서버로 보낼 학생 정보는 `public/js/app.js` 의 `outboundStudent()` 가 이 값을 보고 결정합니다.

```js
function outboundStudent() {
  const st = (state.session && state.session.student) || {};
  if (state.session && state.session.sendName === true) return st;
  return { name: '', school: '', grade: String(st.grade || '') };
}
```

즉 **체크하지 않으면 이름과 학교는 빈 값으로 바뀌어 나가고, 학년만 나갑니다.** (학년은 보고서 말투를 맞추는 데 쓰입니다.) 이름 자리가 비면 AI에게는 `학생` 이라는 일반 문구로 전달됩니다.

| 항목 | 체크 안 함 (기본) | 체크함 |
|---|---|---|
| 이름 | ❌ 나가지 않음 (`학생` 으로 대체) | ✅ 나감 |
| 학교 | ❌ 나가지 않음 | ✅ 나감 |
| 학년 (입력한 글자 그대로) | ✅ 나감 | ✅ 나감 |
| 학교급(초·중·고)과 그 급의 문항 수 | ✅ 나감 | ✅ 나감 |
| 채점 결과 (유형별 점수·백분율·순위, DISC 1·2순위, MBTI 4글자와 지표별 점수, 다중지능 8개 순위와 강점·약점 3개, RIASEC 홀랜드 코드) | ✅ 나감 | ✅ 나감 |
| **개별 문항에 무엇이라고 답했는지** | ❌ **어떤 경우에도 나가지 않음** | ❌ **어떤 경우에도 나가지 않음** |
| 학번 | ❌ 입력란 자체가 없음 | ❌ 입력란 자체가 없음 |
| 접속 IP | ❌ Upstage로는 안 나감 (서버 메모리에 1시간) | ❌ 동일 |

알아 둘 점 몇 가지입니다.

- **학년 칸은 자유 입력**입니다. 학생이 `3학년 2반 15번` 처럼 적으면 그 글자가 그대로 나갑니다. 체크를 꺼도 마찬가지이니, 개인정보가 걱정되면 **학년 칸에는 학년만 적게** 안내하세요.
- 체크를 켰더라도 **브라우저를 새로고침하거나 결과 파일을 다시 불러오면 이 스위치는 다시 꺼진 상태로 돌아갑니다.** 안전한 쪽으로 되돌아가는 동작이므로, 이름을 넣고 싶다면 학생 정보 화면에서 다시 체크하면 됩니다.
- 이름 대신 **번호나 별명**(예: `2-3-15`, `푸른하늘`)을 넣고 체크하면, 개인 식별 없이도 학생이 자기 보고서를 알아볼 수 있습니다. 학급 전체를 인쇄해 나눠 줄 때 이 방식이 편합니다.
- **아예 외부 전송을 원하지 않는다면** `.env` 에서 `UPSTAGE_API_KEY` 를 비워 두세요. 서버가 Upstage를 호출하지 않고 폴백 보고서만 만듭니다.

### 전송 경로

**"AI 종합 진로보고서 만들기"를 누르는 순간에만** 아래 경로로 데이터가 전송됩니다.

```
학생 브라우저 → 교사 PC(또는 배포한 서버) → https://api.upstage.ai (Upstage 서버)
```

전송된 내용이 Upstage 쪽에서 어떻게 처리·보관되는지는 Upstage의 정책을 따릅니다.

> **학교 개인정보 처리방침 검토가 필요할 수 있습니다.**
> 이름을 켜고 쓰면 개인정보(이름·학교·학년)가 국내 민간 AI 서비스로 전송됩니다. 학교에 따라 **개인정보 처리방침 반영, 정보공시, 보호자 동의** 절차가 필요할 수 있으니, 학급 단위로 쓰기 전에 학교 개인정보보호 담당자와 한 번 확인하세요.
> 가장 간단한 방법은 **체크박스를 끈 채로(기본값) 운영하는 것**입니다. 이 경우 외부로 나가는 것은 이름 없는 검사 점수뿐입니다.

## 9. 자주 겪는 문제 해결

### 포트 충돌 — `EADDRINUSE: address already in use :::3000`

3000번 포트를 이미 다른 프로그램(또는 앞서 켜 둔 이 서버)이 쓰고 있다는 뜻입니다.

- **가장 쉬운 해결:** `.env` 에서 포트 번호를 바꾸고 서버를 다시 켭니다.
  ```
  PORT=3100
  ```
  접속 주소도 `http://localhost:3100` 으로 바뀝니다.
- 앞서 켜 둔 창이 남아 있는 것이 원인일 때가 많습니다. 열려 있는 터미널 창에서 `Ctrl + C` 를 눌러 끄세요.
- 그래도 안 되면 누가 쓰는지 확인합니다.
  ```
  netstat -ano | findstr :3000
  ```
  맨 오른쪽 숫자가 PID입니다. 그 프로그램이 꺼도 되는 것이라면
  ```
  taskkill /PID 12345 /F
  ```

### 키 오류 — AI 대신 자꾸 기본 보고서가 나옴

1. 브라우저에서 `http://localhost:3000/api/health` 를 열어 봅니다.
   - `{"ok":true,"hasKey":true,"model":"solar-pro4"}` → 키는 읽혔습니다. 3번으로.
   - `"hasKey":false` → 키를 못 읽었습니다. 2번으로.
2. `hasKey:false` 일 때 확인할 것
   - 파일 이름이 정확히 `.env` 인가요? (메모장이 `.env.txt` 로 저장했을 수 있습니다. 탐색기에서 "파일 확장명" 표시를 켜고 확인하세요.)
   - `.env` 가 `server.js` 와 **같은 폴더**에 있나요?
   - `npm start` 를 프로젝트 폴더 안에서 실행했나요? 다른 폴더에서 실행하면 `.env` 를 못 찾습니다.
   - 줄이 `UPSTAGE_API_KEY=up_...` 형태인가요? 따옴표, 앞뒤 공백, `KEY = 값` 같은 띄어쓰기는 문제를 일으킵니다.
   - **.env 를 고친 뒤 서버를 재시작했나요?** (가장 흔한 원인입니다.)
3. `hasKey:true` 인데도 폴백이면 서버를 띄운 터미널 창을 보세요. 이런 줄이 찍힙니다.
   ```
   [report] AI 호출 실패(중학생) → 폴백 보고서로 대체: Upstage 401 ...
   ```
   - **401 / 403** → 키가 틀렸거나 폐기됐습니다. 콘솔에서 키를 새로 발급받으세요.
   - **429** → Upstage 쪽 요청 한도입니다. 잠시 뒤 다시 시도하세요.
   - **404 / model** 관련 → `UPSTAGE_MODEL` 이름이 잘못됐을 수 있습니다. `solar-pro4` 로 되돌려 보세요.
   - **연결/타임아웃** → 학교망이 `api.upstage.ai` 를 막고 있을 수 있습니다. 휴대폰 핫스팟으로 한 번 시험해 보면 원인을 가릴 수 있습니다.

### 보고서가 너무 짧게 나옴

- 먼저 **기본 분석 엔진(폴백)으로 만들어진 것은 아닌지** 확인하세요. 보고서 위쪽 모델 표시가 `rule-based` 이면 폴백입니다. 위의 "키 오류" 항목대로 원인을 찾으세요.
- **학교급에 따라 분량이 원래 다릅니다.** 서버가 잡아 두는 응답 최대 길이가 초등 5000 / 중학 7000 / 고교 9000 토큰(`server.js` 의 `MAX_TOKENS`)입니다. 초등 보고서가 고교보다 짧은 것은 정상입니다.
- AI 보고서인데 짧다면 **"🔄 다시 생성"** 을 한 번 눌러 보세요. 생성 결과는 매번 조금씩 달라집니다.
- 생성 도중 창을 닫거나 새로고침하면 연결이 끊겨 내용이 잘립니다. 1~2분 동안 그대로 두세요(앱도 이때 한 번 물어봅니다).
- **1시간에 30회** 넘게 보고서를 만들면 그 IP는 자동으로 폴백으로 내려갑니다(차단이 아니라 강등). 1시간이 지나면 원래대로 돌아옵니다. 스트리밍이 실패해 일반 방식으로 자동 재시도되면 한 번 생성에 2회로 셉니다.
- 그래도 분량이 아쉽다면 `server.js` 의 `MAX_TOKENS` 값을 올리거나, `lib/prompt.js` 의 급별 지침을 손보면 됩니다(아래 10번 참고).

### localStorage 초기화 (저장된 답 지우기)

- **한 검사만 다시 풀리기:** 결과 요약 화면의 검사 카드에 있는 **"다시하기"**, 문항 화면의 **"이 검사 다시하기"**, 그리고 **검사 안내 화면의 "처음부터 다시"** — 이 세 개는 모두 **그 검사 하나만** 초기화합니다. (안내 화면 버튼의 글자가 아래 항목과 같아서 헷갈리기 쉽습니다.)
- **진행 중인 답 전부 지우기:** 결과 요약 화면 맨 아래의 빨간 **"처음부터 다시"** 버튼 — 세션 전체를 지우고 학교급 선택부터 다시 시작합니다. (보관함 기록은 남습니다.)
- **보관함 기록 지우기:** 홈 화면 보관함 목록에서 항목별 **"삭제"** 버튼.
- **이 컴퓨터 기록 전부 지우기:** 홈 화면 맨 아래 **"이 컴퓨터의 기록 모두 지우기"** — 진행 중인 검사와 보관함을 한꺼번에 지웁니다. 공용 PC에서는 이것을 쓰세요.
- **콘솔로 완전히 싹 지우기:** 해당 브라우저에서 `F12`(개발자 도구) → Console 탭에 아래 한 줄을 붙여 넣고 Enter, 그다음 새로고침.
  ```
  localStorage.removeItem('jinro_session_v2'); localStorage.removeItem('jinro_archive_v2');
  ```
  (`_v1` 로 끝나는 예전 키가 남아 있어도 앱이 처음 뜰 때 자동으로 지웁니다.)
- 저장 자체가 안 되는 경우(시크릿 창, 사생활 보호 모드, 저장 공간 가득 참)에는 "이 브라우저에 저장할 수 없어 답이 임시로만 보관돼요"라는 안내가 뜹니다. 이때는 창을 닫으면 답이 사라지므로 **끝내기 전에 반드시 "결과 파일로 저장"** 을 누르게 하세요.

### 저장해 둔 답이 비어서 돌아옴

문항을 고친 뒤에 예전 답을 불러오면 길이가 맞지 않아 일부가 빈 채로 열립니다. 앱이 "저장해 둔 답이 지금 문항과 맞지 않아 일부가 비었어요"라고 알려 줍니다. 이때는 새로 시작하는 것이 맞습니다. (학교급이 없던 예전 버전 파일은 아예 열리지 않습니다.)

## 10. 문항 수정과 프롬프트 수정

### 문항 고치기

문항은 전부 `public/js/data/` 안에 있고, **파일마다 `elem` / `mid` / `high` 세 벌**이 들어 있습니다.

```js
export const DISC_QUESTIONS = {
  elem: [ /* 12문항 */ ],
  mid:  [ /* 20문항 */ ],
  high: [ /* 28문항 */ ],
};
```

| 파일 | 한 문항의 모양 | `type` 에 쓰는 값 |
|---|---|---|
| `disc.js` | `{ text: "문항 내용", type: "D" }` | `D` `I` `S` `C` |
| `mbti.js` | `{ q: "질문", a: "A 선택지", b: "B 선택지", type: "EI" }` | `EI` `SN` `TF` `JP` (a를 고르면 앞 글자, b를 고르면 뒷 글자) |
| `mi.js` | `{ text: "문항 내용", type: "A" }` | `A`~`H` (8개 지능) |
| `riasec.js` | `{ text: "문항 내용", type: "R" }` | `R` `I` `A` `S` `E` `C` |

- **문구만 다듬는 경우**(문항 수는 그대로): 파일을 저장하고 브라우저에서 새로고침하면 끝입니다. 화면이 안 바뀌면 `Ctrl + F5` 로 강력 새로고침하세요. (서버 재시작은 필요 없습니다.)
- **문항 수를 바꾸는 경우**에는 `public/js/data/levels.js` 의 그 급 항목을 함께 고쳐야 합니다.
  - `perScale` — 척도(유형) 하나당 문항 수
  - `counts` — 검사별 문항 수 (`perScale × 척도 개수` 와 일치해야 함)
  - `total` — 그 급의 전체 합계
  - `estMinutes` — 그 급의 예상 시간 (검사별 시간은 문항 수 비율로 자동 배분됩니다)
- **채점 만점은 손댈 필요가 없습니다.** `scoring.js` 가 문항 데이터를 세어 유형별 만점을 자동으로 계산합니다. 프롬프트에 들어가는 "유형당 몇 문항, 몇 점 만점" 문구도 `levels.js` 의 `perScale` 에서 자동으로 만들어집니다.
- 고친 뒤에는 **반드시 검증기를 돌리세요.**

  ```
  npm run check
  ```

  문항 수, 유형별 개수 균등, MBTI a/b 선택지 누락·중복, 같은 문장 중복까지 한국어로 짚어 줍니다. 통과하면 이런 요약이 나옵니다.

  ```
  학교급별 문항 수
    🌱 초등학생 — 합계 66문항 (DISC 행동유형 12 / MBTI 성격유형 12 / 다중지능(MI) 24 / RIASEC 직업흥미 18)
    🌿 중학생 — 합계 110문항 (DISC 행동유형 20 / MBTI 성격유형 20 / 다중지능(MI) 40 / RIASEC 직업흥미 30)
    🌳 고등학생 — 합계 154문항 (DISC 행동유형 28 / MBTI 성격유형 28 / 다중지능(MI) 56 / RIASEC 직업흥미 42)
  ```

  이 검사는 깃허브에 push할 때도 자동으로 돕니다(`.github/workflows/ci.yml`).
- ⚠️ 문항 수가 달라지면 **이미 저장된 학생 답안은 어긋납니다.** 학기 중에는 바꾸지 말고, 바꿨다면 학생들에게 새로 시작하게 안내하세요.
- 유형 설명 글(결과 화면과 폴백 보고서에 나오는 문장)은 `disc.js`, `mbti-results.js`, `mi-types.js`, `riasec.js` 안에 있고, 초등용 쉬운 말 버전은 이름 끝에 `_EASY` 가 붙어 있습니다. 학교 실정에 맞게 예시 활동이나 과목명을 바꾸기 좋은 부분입니다.

### 프롬프트 고치기 (`lib/prompt.js`)

AI에게 보내는 지시문은 이 파일 하나에 모여 있고, 네 덩어리로 나뉩니다.

| 이름 | 내용 | 고쳐도 되나 |
|---|---|---|
| `PERSONA` | 상담자 역할, 어조, 보고서 1~5장 상세 구조("강점 5가지", SWOT 등) | **손대지 마세요.** 사용자가 제공한 원문 그대로 보존하는 부분입니다. |
| `OUTPUT_RULES` | 마크다운 형식, 표 금지, 서두·맺음말 금지 | 마크다운 관련 항목은 그대로 두세요. 흐트러지면 화면 렌더링이 깨집니다. |
| `LEVEL_RULES` (`ELEM_RULES` / `MID_RULES` / `HIGH_RULES`) | 급별 말투, 금지어, 학교 제도 연결, 학과 추천 범위 | **여기를 고치세요.** 급별 조언을 바꾸고 싶을 때 손댈 곳은 여기뿐입니다. |
| `ERA_2026` | 2026년 관점 공통 지침 (모든 급 뒤에 붙음) | 필요하면 고쳐도 됩니다. |

- 예시 수정: 중학 보고서에서 고교 유형 이야기를 빼고 싶다면 `MID_RULES` 의 "고등학교 유형 힌트" 단락을 지웁니다. 고교 보고서에 특정 지역 대학 이야기를 넣고 싶다면 `HIGH_RULES` 의 "학과 추천의 범위"를 고칩니다.
- **이 파일은 서버 코드이므로 고친 뒤 서버를 반드시 재시작**해야 합니다(`Ctrl + C` → `npm start`, 또는 `npm run dev` 로 실행해 두면 자동 재시작).
- 응답 길이·창의성은 `server.js` 의 `temperature: 0.7`, `MAX_TOKENS`(급별 5000/7000/9000), `reasoning_effort: 'low'` 에서 조절합니다.
- 프롬프트를 바꾼 뒤에는 **교사가 세 학교급 모두 한 번씩 끝까지 돌려 보고** 학생에게 배포하세요. AI 출력은 지시문 한 줄에도 크게 달라집니다.
- 폴백 보고서 문구를 바꾸려면 `lib/fallback.js` 를 고칩니다. 이쪽도 서버 재시작이 필요합니다.

## 11. 이 검사의 한계 (학생·학부모에게 꼭 안내해 주세요)

> **이 검사 결과는 공식 표준화 심리검사가 아니라, 학생이 스스로를 이해하는 데 도움을 주기 위한 참고 자료입니다.**
> 표준화된 규준(같은 또래 집단과 비교하는 기준)이나 신뢰도·타당도 검증을 거치지 않았습니다.
> **이 결과로 학생을 규정해서는 안 되며, 선발·배치·진단의 근거로 사용해서는 안 됩니다.**
> 반 편성, 동아리 배정, 진로 트랙 배치, 상담 대상자 선정 등 학생에게 실질적 영향을 주는 결정에 이 결과를 쓰지 마세요.

구체적으로 이런 한계가 있습니다.

- **자기보고식 검사입니다.** 학생이 스스로 고른 답을 그대로 합산하므로, 기분·컨디션·"좋아 보이고 싶은 마음"에 따라 결과가 달라집니다. 같은 학생이 한 달 뒤 다시 하면 유형이 바뀔 수 있습니다.
- **규준이 없습니다.** 백분율은 또래와 비교한 값이 아니라 **그 검사에서 받을 수 있는 최고점 대비 비율**입니다. "80%"는 상위 20%라는 뜻이 아닙니다.
- **학교급마다 문항 수가 다릅니다.** 초등 66문항과 고교 154문항의 결과를 **같은 잣대로 비교할 수 없습니다.** 같은 학생이 학교급을 바꿔 다시 풀어도 결과는 달라집니다.
- **공식 검사와 다릅니다.** MBTI®는 등록 상표이며 자격을 갖춘 전문가가 시행하는 공식 검사가 따로 있습니다. 이 앱의 문항은 교육용으로 재구성된 것으로, 공식 MBTI 검사도 공인 DISC 검사도 아닙니다.
- **AI 보고서는 창작된 글입니다.** 점수 자체는 정확하지만, 그 점수를 풀어 쓴 문장·추천 학과·추천 직업·추천 과목은 AI가 생성한 내용이라 사실과 다르거나 매번 달라질 수 있습니다. 학생에게 나눠 주기 전에 교사가 한 번 읽어 보기를 권합니다.
- **사람을 네 글자나 한 유형으로 가두지 않도록** 지도해 주세요. 특히 학급에서 "너는 무슨 형이야?"가 놀림이나 편 가르기로 이어지지 않게, 결과 공개는 강요하지 않는 것이 좋습니다.
- 진학·진로 결정에 실제로 활용할 공신력 있는 검사가 필요하다면 **커리어넷(진로심리검사)이나 워크넷의 직업심리검사**, 또는 전문 상담기관을 함께 안내해 주세요.

수업 도입부에 이 문단을 함께 읽고 시작하면, 학생들이 결과를 "정답"이 아니라 "나를 들여다보는 거울"로 받아들이는 데 도움이 됩니다.
